## 1. Предметная область

Приложение «Погодное оповещение» предназначено для отслеживания погодных условий и отправки уведомлений пользователю при наступлении определённых событий.

**Основные функции:**
1. Получение текущей погоды.
2. Получение прогноза на несколько дней.
3. Обновление информации о погоде.
4. Отправка оповещений (например, при снижении температуры ниже заданного порога).

---

## 2. Реализованные методологии

В рамках проекта последовательно применены четыре подхода к разработке через тестирование.

### 2.1. TDD (Test-Driven Development)
Разработка велась по циклу **Red → Green → Refactor**. Сначала создавались юнит-тесты, описывающие ожидаемое поведение классов `WeatherService` и `WeatherAlert`. На этапе Red-фазы тесты падали с ошибкой `ModuleNotFoundError`, после реализации кода — успешно проходили.

*   **Инструменты:** `unittest` (стандартная библиотека Python).
*   **Файл тестов:** `test_weather.py`.

### 2.2. ATDD (Acceptance Test-Driven Development)
Сформулированы приёмочные сценарии, отражающие требования заказчика:
*   *Сценарий 1:* При температуре −10 °C и пороге −5 °C — оповещение отправляется.
*   *Сценарий 2:* При температуре +15 °C и пороге −5 °C — оповещения нет.

*   **Инструменты:** `unittest` с перехватом `stdout` для проверки текста сообщения.
*   **Файл тестов:** `test_acceptance.py`.

### 2.3. BDD (Behavior-Driven Development)
Поведение системы описано на языке **Gherkin** с использованием русскоязычного синтаксиса (`# language: ru`). Сценарии автоматизированы через фреймворк **Behave**.

*   **Инструменты:** Behave.
*   **Файлы:** `features/weather_alerts.feature`, `features/steps/weather_steps.py`.

### 2.4. SDD (Specification by Example)
Требования зафиксированы в виде таблицы конкретных примеров (Specification by Example). На её основе создан параметризованный тест (Data-Driven Test), который при каждом запуске проверяет соответствие реализации спецификации.

*   **Инструменты:** `pytest` (`@pytest.mark.parametrize`).
*   **Файл тестов:** `test_sdd.py`.
